## 1. 新增功能：注入法术（Imbue）

### 需求背景

铁魔法原版的注入流程是：拿到法术卷轴 → 放进奥术铁砧（Arcane Anvil）→ 对准可注入的武器/盔甲合成。
注入完成后：

- **武器**（主手 / 副手）：**手持**该物品，法术就出现在法术轮盘上，可以直接施放；
- **盔甲 / Curios 饰品**：**穿戴**后法术才出现在法术轮盘上。

本版本把这条链路做进测试台：选中一个法术 → 选一个槽位 → 一键注入，
不再需要为了测一把武器来回跑奥术铁砧，也不用先刷卷轴。

### ISS 侧的实现依据（1.20.1-3.16.3）

写入的是 ISS 的法术容器 NBT，走的是和奥术铁砧**完全相同**的官方入口，不是自己拼 NBT：

```java
// io.redspace.ironsspellbooks.api.spells.ISpellContainer
static ISpellContainer createImbuedContainer(AbstractSpell spell, int level, ItemStack stack) {
    boolean mustEquip = stack.getItem() instanceof ArmorItem
                     || stack.getItem() instanceof ICurioItem;
    var container = create(1 /*maxSpells*/, true /*isSpellWheel*/, mustEquip).mutableCopy();
    container.addSpellAtIndex(spell, level, 0, true /*locked*/);
    var immutable = container.toImmutable();
    set(stack, immutable);   // 写进 stack 的 irons_spellbooks:spell_container
    return immutable;
}
```

关键点：

- `isSpellWheel = true`：法术才会进轮盘（卷轴容器这里是 `false`，所以卷轴不能当注入目标用）；
- `mustEquip`：**由 ISS 自己按物品类型判定**，不是我们传的 ——
  盔甲和 Curios 饰品为 `true`（必须穿戴），武器为 `false`（手持即可）。
  所以本模组完全不需要自己判断「手持生效还是穿戴生效」，照搬官方入口即可；
- `locked = true`：与奥术铁砧一致，注入的法术不能在抄写台里被取出/替换。

（`createImbuedContainer` 的字节码、以及 ISS 自带的 `createImbuedSword` 命令，
是对本地 Gradle 缓存里的 `irons_spellbooks-1.20.1-3.16.3-api.jar` / 完整模组 jar 反编译确认的。）

### 本模组的做法

**`spell/SpellImbueManager.java`（新增，服务端权威）**

| 环节 | 处理 |
| --- | --- |
| 权限 | 与其它操作一致走 `PermissionHelper.canUse`（默认创造模式，可用 `/rsta unlock` 解除） |
| 等级 | 显式给了就用给定值；`<=0` 时取玩家「等级规则」的下限（固定等级模式即固定等级），并 `clamp` 到 `spell.getMaxLevel()` |
| 目标校验 | 槽位为空 / 物品不可注入 / 槽位已满，分别给出各自的提示语言键 |
| 写入 | 无容器 → `ISpellContainer.createImbuedContainer(...)`（官方语义）；已有容器且开启追加 → `get().mutableCopy()` 后 `addSpellAtIndex` 追加 |
| 重复法术 | `addSpellAtIndex` 失败时按 `getIndexForSpell` 找到原条目替换，保证一个法术只占一个槽位 |
| 回写 | `copy → 改 → setStack`，改完 `inventory.setChanged()` + `inventoryMenu.broadcastChanges()` 同步到客户端 |
| 清除 | `ISpellContainer.remove(stack)`，等效原版忏悔石 |

**可注入判定 `isImbueable()`**（默认严格，等价奥术铁砧的接受范围）：

- `SwordItem`（含 ISS 的 `MagicSwordItem extends ExtendedSwordItem extends SwordItem`）；
- `ArmorItem`；
- Curios 的 `ICurioItem`；
- 实现了 `IPresetSpellContainer` 的 ISS 物品；
- ISS 法杖/魔杖等非剑武器（`StaffItem extends CastingItem extends Item`，不是 `SwordItem`，
  且位于非 API 包无法编译期引用）→ 按包名 `io.redspace.ironsspellbooks.item.weapons.` 兜底识别；
- 卷轴（`IScroll`）**永远排除**：卷轴容器 `isSpellWheel=false`，注入了也不会进轮盘。
- 服务端配置 `imbue.allowAnyItem = true` 时可放开到任意物品（默认 `false`）。

**`spell/ImbueTarget.java`（新增枚举）**：`MAINHAND / OFFHAND / HEAD / CHEST / LEGS / FEET`。
手持槽走 `setItemInHand`（语义明确无歧义），盔甲槽走 `setItemSlot`；携带 `key()`（命令参数/网络包载荷）与 `translationKey()`。

### 交互入口

**GUI（右控制台「操作」区，排在「生成卷轴」之前）**

| 控件 | 行为 |
| --- | --- |
| `注入目标: 主手` | 循环按钮，主手 → 副手 → 头盔 → 胸甲 → 护腿 → 靴子 |
| `注入法术` | 把当前选中法术按等级规则注入到目标槽位（未选中法术时置灰） |
| `清除注入` | 清掉目标槽位物品上的注入法术（不依赖选中法术，始终可用） |

注入/清除**都不关闭界面**（结果走 actionbar），方便连着换法术、换槽位继续测。

**命令**

```
/rsta imbue <法术> [等级] [目标]
/rsta unimbue [目标]
```

`目标` 可填 `mainhand / offhand / head / chest / legs / feet`，省略时默认主手。
`等级` 省略时与 GUI 一致，取玩家等级规则下限。

### 新增服务端配置（`randomspellbench-server.toml` → `[imbue]`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `allowAnyItem` | `false` | true = 任意物品都能注入（不再限制武器/盔甲/饰品） |
| `maxSpellsPerItem` | `3` | 单个物品最多注入几个法术 |
| `appendToExisting` | `true` | 已有注入时追加而非覆盖 |

## 2. 需要验证的操作

1. 手持一把钻石剑，`/rsta config` 打开测试台 → 选中任意法术 → 目标保持「主手」→ 点「注入法术」；
   actionbar 提示成功，剑的 tooltip 上出现该法术，**手持**时打开法术轮盘能看到并施放。
2. 换目标到「胸甲」，穿一件胸甲后注入 → 轮盘上出现；**脱下**胸甲后轮盘上消失（验证 `mustEquip`）。
3. 连续注入 2 个不同法术到同一把剑 → 两个法术都在；注入第 4 个时提示「槽位已满（上限 3）」。
4. 点「清除注入」→ 物品回到未注入状态（tooltip 上法术消失）。
5. 空手注入 → 提示「主手 槽位没有物品，无法注入」；拿草方块注入 → 提示「不能注入法术（只支持武器 / 盔甲 / 饰品）」。
6. 命令行 `/rsta imbue irons_spellbooks:fireball 5 head` → 头盔被注入火球术 Lv5。
7. 非创造模式玩家（未 `/rsta unlock`）执行注入 → 与其它操作一致，被创造模式限制拦下。
